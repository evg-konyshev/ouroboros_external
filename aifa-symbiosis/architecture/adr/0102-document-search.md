# ADR-0102. Поиск по документам: проекция OpenSearch и инструмент `aifa_search`

Статус: принято (24.11.2026, владелец)
Заменяет: ADR-0022 п. 5 (цель бюджета схем)

## Контекст

Многодокументному анализу нужны две вещи, которых нет при чтении целых текстов и поиске по
подстроке (`aifa_doc query`): выбрать нужные документы из папки с десятками отчётов и ответить на
качественный вопрос по нескольким сразу. RFA решает обе пересобираемой проекцией OpenSearch
(`AIFA_RFA/docs/MULTIDOCUMENT_TECHNICAL_SPEC.md` §6, `src/finengine/retrieval/`). Изменение
`openspec/changes/aifa-document-search` её переносит.

Факты:
- Распознавание — фоновая задача FastAPI `_parse_doc_in_background` (`api/main.py:482`): текст
  со страницами `===PAGE N===`, затем мета-карточка (`doc_kind`, `issuer`, `issuer_aliases`,
  `period`, `skills/meta_card.py`). Воркера, аренды и повторов нет.
- Каждая запись реестра заменяет весь JSON `meta` (`store/documents.py`, upsert'ы
  `api/main.py:580-606`, правка типа `api/main.py:1390`), поэтому новый ключ в `meta` теряется.
- Кода эмбеддингов нет; SDK `gigachat` и `openai` уже в зависимостях.
- F4: снимок схем — 6127 знаков из цели 7000 (ADR-0022 п. 5), предел ядра 8000. Ouroboros молча
  пропускает схему расширения, не уместившуюся в бюджет (`ouroboros/agent/task_graph.py:179-187`).
- `СБОЙ_СЛУЖБЫ` пишет плагин, и он велит повторить вызов (`CONTRACTS.md` §3.0).

## Решение

### S1. Перенос RFA `retrieval/` в `finengine/search/`, вход — только текст
- Модули с именами RFA: `client.py`, `index_schema.py`, `card.py`, `chunker.py`, `embeddings.py`,
  `indexing.py`, `search.py`, `reindex.py` (CLI).
- Один индекс за алиасом, две записи: `document` (карточка) и `chunk`. У каждой — `document_id`
  и `workspace_id` (ADR-0101); id детерминированы; переиндексация заменяет все чанки документа.
- Правила чанков — RFA: окно предложений 800/100; чанк не пересекает страницу, таблицу и
  Markdown-раздел; повторённая проза — один раз; таблица не делится; страница финансовой
  отчётности без таблиц — целиком. Локатор `{page, section_path}`.
- Отличие от RFA — только поиск таблиц: Markdown-таблицы (`|…|` со строкой `|---|`) в тексте
  страницы из `doc_pages.pages_of`; OCR JSON не хранится.
- Карточка: компания, тип, период — сначала из мета-карточки, затем из `DocumentMeta`;
  `company_key` — перенос RFA `analytics/company_key.py`; до 20 заголовков без подписей таблиц;
  короткое описание собирает код. Поиск по карточкам отдаёт только id и оценки.

### S2. Эмбеддинги — API-провайдер, одна модель на индекс
- `FINENGINE_EMBEDDING_PROVIDER=gigachat|openrouter`, модель, размер пачки; локальной модели нет
  (правило RFA T20).
- `_meta` индекса хранит провайдера, модель и размерность; запись с другой моделью или
  размерностью отклоняется («нужна пересборка»).
- Текст документа уходит провайдеру эмбеддингов — тот же класс данных, что уже уходит модели чата.

### S3. Индексация — в той же фоновой задаче; состояние — своя колонка
- После последнего `add_document` в `_parse_doc_in_background` — `indexing.index_document` в
  `try`; сбой не роняет загрузку.
- Итог (`indexed` | `failed:<причина>`) — колонка `document.index_state` через
  `set_index_state`: одноколоночный `UPDATE … WHERE doc_id`. Удалённый документ она не
  воссоздаёт, писатели всего `meta` её не трогают. Колонку добавляет DDL старта store
  (`ADD COLUMN IF NOT EXISTS`, механизм ADR-0101 W3).
- `delete_document` после удаления строки реестра удаляет записи проекции best-effort.

### S4. Согласованность — перепроверкой и сверкой с самим индексом
- Каждое попадание проходит `get_document` + `_user_can_see` + `document_text_exists` + допустимый
  набор. Запись проекции доступа не даёт.
- `reindex --reconcile` сравнивает готовые документы реестра с id карточек в индексе (scroll по
  `record_kind=document`): нет карточки — индексировать, карточка без документа — удалить.
  `index_state` одному не доверяет. `--rebuild` строит новый индекс, переключает алиас и
  заканчивается сверкой. Обе команды повторяемы.

### S5. Поиск всегда двухстадийный, по допустимым id; workspace — необязательный фильтр
- `select_documents(allowed_ids, query, mode="hybrid", workspace_id=None)`: RRF k=60 над BM25
  карточек, kNN карточек и владельцами лучших чанков.
- `retrieve_chunks(doc_ids, query, k, mode="hybrid")`: BM25 + kNN, RRF k=60, только внутри
  выбранных документов.
- Вызов без `doc_ids` — сначала выбор, затем чанки выбранных; с `doc_ids` первая стадия
  пропускается. Пула по всем допустимым документам сразу нет.
- `mode`: `hybrid` (по умолчанию) или `lexical` — только BM25, без вызова эмбеддингов, на обеих
  стадиях. Размер пула — RFA `pool_size(candidate_size, documents=len(allowed_ids))`.
- `aifa_search` workspace не передаёт (ход `conversation` может держать документы нескольких
  папок); фильтр передаёт `aifa-multi-document-turn` для `all_workspace`.

### S6. Инструмент `aifa_search`, код `поиск_недоступен`, бюджет схем
- `aifa_search(query, doc_ids?, limit?, mode?)`: только чтение, вне очереди, доступен после
  `aifa_open` ровно тогда, когда `aifa_doc`; `doc_ids` ⊆ документов хода, иначе
  `ОТКАЗ нет_документа`; `limit` 1–10, иначе `неверные_аргументы`. Ответ — чанки с doc id,
  страницей, разделом и текстом в пределах `result_limit` (`ouro_view.search_hits`).
- Новый код отказа `поиск_недоступен` (`Refusal.SEARCH_DOWN`) — только при сбое провайдера
  эмбеддингов (текст называет `mode="lexical"`, без «повтори») и когда недоступны и индекс, и
  тексты. `СБОЙ_СЛУЖБЫ` остаётся за плагином.
- F4/F9: `OUROBOROS_INITIAL_EXTENSION_SCHEMA_BUDGET=10000` в окружении aifa-sym (путь ADR-0027).
  Расчёт: снимок 6127 + оценка `aifa_search` 600–800, `aifa_compare` 600–800 и
  `doc_id`/`offset` примерно у семи инструментов 500–700 даёт 7,8–8,4 тыс. знаков, что не
  помещается в прежнюю цель 7000. Поэтому цель F4 — 9000, предел — 10000, запас 1000 как в
  ADR-0022. Это примерно 3–4 тыс. токенов, или 2–3% контекстного окна 131–200 тыс. Бюджет
  остаётся абсолютным: ядро считает знаки (`task_graph.py:179-187`), а F1 замораживает ядро.
  `test_schema_budget.py` читает предел из `aifa/contracts/dev_config.snapshot.json`, по-прежнему
  проверяет `total <= TARGET_CHARS < limit` и значение по умолчанию ядра 8000. Измеренный размер
  снимка после изменения: 6608 знаков.

### S8. Отказ OpenSearch — деградированный ответ, не отказ
- При недоступном OpenSearch инструмент ищет подстроку (без учёта регистра) в опубликованных
  текстах допустимых документов: документы — по полям карточки из Postgres, места — со
  страницами, в пределах размера ответа (S9). Эмбеддинги не вызываются.
- Ответ помечен как деградированный в данных и в тексте `ouro_view`; пометка входит в снимки
  контрактов. Доступ перепроверяется как в S4.

### S9. Размер ответа по запросу, когда `limit` не задан
- Детерминированный классификатор строки запроса без вызова модели: числа, %, единицы или слова
  показателей («выручка», «прибыль», «рентабельность», «капитал», «дивиденды») — узкий запрос,
  3 чанка; иначе — широкий, 8. Границы калибруются на бенчмарке задачи 6.3. Явный `limit`
  всегда главнее.

### Инфраструктура
- Сервис `opensearch` в compose aifa-sym: точный тег 2.x, один узел, плагин безопасности
  выключен (только внутренняя сеть), heap 1 ГБ, том `os-data`. Служба знает его только по
  `FINENGINE_OPENSEARCH_URL`, без `depends_on`, и стартует и распознаёт без него.
- Зависимость `opensearch-py` в `aifa/finengine` (точная версия фиксируется при подтверждении
  владельцем, задача 1.2).

### Non-goals
- Нет воркера индексации, аренды и машины состояний документа: сверка покрывает потерянное.
- Нет расширения соседними чанками (RFA §6.3).
- Нет локальной модели эмбеддингов и плагина безопасности OpenSearch.
- Нет OCR JSON и отдельной разбивки таблиц-файлов (RFA `_spreadsheet_chunks`).
- Нет добора внутри вытесненных документов (RFA `test_analysis_retrieval.py`).

## Следствия
- `aifa-multi-document-turn` выбирает документы хода через `select_documents` с workspace.
- Хосту dev — примерно 1 ГБ памяти и том индекса; перед выкаткой проверяются `df -h` и память.
- Набор инструментов, перечень отказов и окружение ouroboros меняются: снимки `tools.snapshot.json`,
  `tool_names.json` (`aifa_search → read_source`), `dev_config.snapshot.json`.
- Откат: убрать инструмент из `OUROBOROS_ENABLED_TOOLS`, остановить `opensearch`; распознавание
  не затронуто, колонка `index_state` инертна.
