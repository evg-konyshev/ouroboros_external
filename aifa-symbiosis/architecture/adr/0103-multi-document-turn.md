# ADR-0103. Один ход AIFA по нескольким документам

Статус: принято (24.11.2026, владелец)
Заменяет: правило очереди на `LoopSession` из ADR-0043 п. 4 и ADR-0092. Дополняет ADR-0015, ADR-0101 и ADR-0102.

## Контекст

`assistant/loop_opening.py` выбирает один отчёт на ход. У каждого отчёта свой паспорт и
реестр показателей, а `Case` уже хранит несколько активных версий документов. Отдельный
цикл на отчёт позволяет использовать существующие паспорт и реестр для каждого документа.

## Решение

1. `POST /chat/turns` принимает `scope` (D7). Значение `conversation` по умолчанию сохраняет
   набор чата, включая доступный активный документ. При явном `all_workspace` берутся все
   документы рабочей области, включая нераспознанные. Непустой `doc_ids` сужает этот набор.
   Активный документ сохраняется только внутри выбранного набора. `project_id` задаёт область,
   если она принадлежит вызывающему и присутствует как папка в его сохранённых диалогах.
   Иначе берётся `owner:<id>`. Чужие документы отфильтровываются, набор фиксируется в
   `TurnRecord`, неизвестный `scope` даёт HTTP 422, а `pinned_tool` игнорирует выбор области.
   Включённый переключатель «Все документы папки» отправляет `all_workspace` и пустой
   `doc_ids`. Интерфейс показывает имена из `turn_documents` (дополнение к ADR-0015).
2. `aifa_doc` перечисляет документы по метаданным реестра и карточки, с готовностью текста,
   числом страниц и числом фактов активной версии в `Case` (D6, D14). `offset` отсчитывает
   записи, `next_offset=null` означает конец. Запрос `query` без `doc_id` ставит совпадения
   поиска первыми, затем оставшиеся документы в порядке хода. При сбое поиска остаётся
   исходный порядок с отметкой о недоступном ранжировании. Число страниц пишется после
   публикации текста в `document.text_pages`; для старых распознанных документов оно
   вычисляется при первом чтении списка. `document.profile_id` записывается при открытии
   цикла. Обе колонки добавляются при старте и обновляются отдельно от `meta`.
3. `aifa_open` от корня выбирает явный `doc_id`, затем единственный, затем активный документ
   хода (D1, D2, D4). Для нескольких документов без выбора, отсутствующего или неготового
   отчёта возвращается `нет_документа`. Ключ отчётного цикла и заявки на открытие —
   `run_id/doc_id`, вид фонового задания — `aifa_open:<doc_id>`. Рыночный цикл сохраняет
   ключ `run_id`; совмещать его с отчётными нельзя. `LOOP_INDEX` хранит порядок открытых
   отчётных циклов и срок хода. Седьмой отчётный цикл получает `лимит_циклов`. Циклы
   восстанавливаются из отдельных снимков только при наличии текста отчёта, при очистке
   удаляются индекс и все снимки хода (D8). `aifa_doc` и `aifa_search` проверяют семейство
   заданий открытия.
4. Одна очередь на ход сериализует `aifa_move`, `aifa_register_atom`, `aifa_finish` и
   открытие отчётного цикла (D3). Ожидание открытия входит в бюджет его задания.
   Очередь защищает индекс циклов и ревизию общего `Case` от одновременных изменений.
   Срок хода равен времени открытия первого отчётного цикла плюс его лимит (D11).
   Поздние циклы наследуют этот срок, он сохраняется при восстановлении, и им же
   ограничивается `aifa_wait(task_id)`.
5. `aifa_move`, `aifa_register_atom`, `aifa_report`, `aifa_atoms` и состояние отдельного
   цикла в `aifa_state` принимают `doc_id` (D4, D8, D12, D13, D15). При одном открытом
   цикле аргумент можно опустить. При нескольких отсутствие аргумента даёт
   `неверные_аргументы` со списком циклов без расхода хода и роста серии отказов.
   Исключение — `aifa_state()`, который возвращает обзор с открытыми циклами, их
   документами, `profile_id` и лимитами ходов, ещё не открытыми документами и общим сроком.
   Артефакты читаются по всему `Case`. Удалённый документ даёт `нет_документа`.
   Подзадачи наследуют транспорт корня и передают `doc_id` из текста задачи. Каждый цикл
   передаёт свой замороженный паспорт при планировании и проверке.
6. `aifa_finish` выполняет проверку на первом цикле, принимает свидетельства всего
   `Case` (в том числе предыдущих ходов), закрывает остальные циклы и публикует один
   результат (D5, D14). `ПРИНЯТО` содержит имена открытых отчётов, а SSE
   `turn_documents {document_ids}` перед `typed_result` передаёт их идентификаторы экрану.
   После завершения изменяющие вызовы получают `цикл_закрыт`.

## Следствия

- Вызовы `aifa_move` по документам идут последовательно. Планировщик переиспользует факты `Case` и
  открывает циклы только для недостающих данных. Пять последовательных циклов проверяются
  на стенде по общему сроку хода.
- В отличие от RFA, область `all_workspace` показывает нераспознанные документы. Их
  обработка по этому запросу не запускается. Переносятся выбор документов и многодокументный
  ход; вне объёма остаются аренда документа и воркеры RFA, автоматическое сужение,
  резолвер диалога и slot deltas, `AnalysisRun` и его идемпотентность, `llm_balancer`,
  конвертация валют и вызов `set.assemble`/`calc.series` между циклами. Сравнительные
  пресеты отнесены к шагу B. Ядро ouroboros сохраняет текущие транспорт, планы и сроки.
- При смене ключей незавершённые циклы предыдущей версии теряются, артефакты `Case`
  сохраняются. Для отката после возврата прежних образов очищаются ключи `ouro_turn:*`:
  старая версия не понимает новые поля записи хода. Для очистки снимков в SQL-хранилище
  используется запрос с параметрами конкретного владельца и хода:
  `DELETE FROM state WHERE owner_key = :owner AND ((kind = 'loop_index' AND key = :run) OR (kind = 'loop_session' AND starts_with(key, :run || '/')))`.

## Чем проверяется

C1.2, C3.12–C3.15, F4 и F13. Сценарии одного отчёта проходят прежние контрактные тесты,
а общие SSE-фикстуры проверяют новое событие на стороне службы и фронтенда.
