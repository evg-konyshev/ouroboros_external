# Ревью шага B. Сравнение фактов Case

25.11.2026. Реализация `2486860..fd04c39`, доработка `85e0636`,
решение ADR-0105 в `2b3adb8` и `8d22848`. Проверены OpenSpec D9/D14, C3.16,
INVARIANTS, DEVELOPMENT §Coding Rules, REVIEW_GUIDE и RFA `14ed8859`.

## Standards

- Чтение именованных фактов и активных версий собрано в один снимок Case. PostgreSQL
  проверен с заменой активного документа между двумя чтениями. Выбор ограничен
  совпадающими id и старыми строками без индекса id. Если версия соответствует
  нескольким документам, ответ сообщает о неоднозначности. `store/cases.py:509`,
  `assistant/compare_tool.py:66`, `test_compare_tool.py`.
- Экраны получают имя инструмента `read_source` согласно D16. Непоказанные строки
  перечисляются после нормализации имён. `assistant/tool_names.py:18`,
  `assistant/ouro_view.py:502`.

## Spec

- Единицы на акцию сохранены. Форму периода задаёт самая новая точка. Для сравнения
  компаний сначала проверяется стандарт, затем выбирается одна точка на компанию.
  Сверка источников даёт отдельный разброс для каждой базы. Факты без определённой
  компании исключаются. `skills/cross_document.py:127`, `:230`, `:298`, `:409`.
- Для известных id сравнение работает до открытия. Для поиска id действует ADR-0104:
  индекс фактов читается после попытки открыть цикл. Сценарий первого вызова
  `aifa_compare` с известными id прошёл через реальный плагин и HTTP.
  `skills/aifa-planning/SKILL.md`, `test_multi_document_turn.py`.
- Вывод ограничен бюджетом по целым строкам. При малом остатке длинный перечень имён
  сокращается с сохранением числа непоказанных строк.

Целевые тесты вычислений, происхождения и изоляции дали 25 успешных проверок,
включая PostgreSQL. F4/F9/F13 прошли. Сквозная проверка использует SQLite согласно
локальному профилю contract. Сценарий на `aifa-sym` остаётся открытым.
